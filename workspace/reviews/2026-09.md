# MyThingsLab — full-ecosystem review, 2026-09-13

_Read-only review session, successor to [`2026-08.md`](2026-08.md) (2026-08-24)
and [`2026-07.md`](2026-07.md) (2026-07-12). Same tagging convention:
**MEASURED** (I ran it in this session), **OBSERVED** (read in code, docs or
ledgers), **INFERRED** (reasoned, with the test that would confirm). Counts come

## 1. TL;DR

**August said "stop building and start running." The building resumed, the
running did not — and the one number that would have told us is corrupted.**

The execution record since August is real and large: **291 commits across 33
repos** in 20 days, concentrated exactly where the kernel is (`my-fleet` 89,
`my-things-core` 46, `my-coder` 39). The CAD foundation moved from a label
schema to working mechanism: the four-condition merge gate (`myfleet.accept`),
auth preflight, priority ranking, red-main escalation, the ASK channel armed and
tapped through end-to-end from a phone. Branch protection is now **35 of 39**,
all requiring `test` — the four without are the org profile, the site, and the
typst repos, plus private `study`, where GitHub gates the feature. Mains are green essentially
everywhere. `fleet-dispatch`, the repo the workspace was built around, was
retired and archived. This is not a stalled project.

And yet **`fleet_dispatch` has not dispatched a worker since 2026-07-08 — 67
days.** That was true in August (47 days) and in July (the same eight sessions).
It is the third consecutive review reporting the identical last-dispatch date.

Worse, the evidence base itself has gone bad. The dispatch ledger shows 150
entries today, which looks like a fleet that finally woke up. It is not.
**MEASURED: 144 of 149 inter-entry gaps are under five seconds, 142 of them
sub-second** — that is a test suite writing to the production ledger, not a
timer firing. Every one is a `fleet_cycle` `bookkeeping` heartbeat with outcome
`ok`. Zero are `fleet_dispatch`. This is [`my-fleet#74`][74], filed, open, and
carrying no `lane`/`prio` labels, which means the queue that is supposed to
schedule work cannot see the bug that is blinding the queue.

The new finding this cycle is a mechanism bug with org-wide blast radius, and it
is the reason the gate cannot land its own team's work:

> **`paths-ignore` in CI and a required `test` check are mutually exclusive.**
> **20 active repos set `paths-ignore: ["**.md", "dev-ledger/**"]`, and all 20
> of them require `test` to merge** — the overlap is total. A docs-only PR
> therefore never runs `test`, never reports `test`, and can never satisfy
> branch protection. It is not red — it is *absent*, forever.

August's verdict was *stop building, start running*. **This review's verdict is
that "running" was blocked by three specific, small, mechanical defects, none of
which is a capability problem** — the docs-only deadlock, the ledger pollution,
and a backlog whose transferred items are invisible to the ranker. Fix those
three and the loop has nothing left to trip on.

## 3. Findings

### F1 — `paths-ignore` + a required check = a permanently unmergeable PR

**MEASURED.** `my-fleet/.github/workflows/ci.yml:6,10` sets
`paths-ignore: ["**.md", "dev-ledger/**"]` on both `push` and `pull_request`.
`my-fleet`'s branch protection requires the context `test`. A docs-only PR
therefore triggers no workflow, so no `test` check-run is ever created.

The proof is on `main` right now. [`my-fleet#81`][81] ("docs: rewrite the
workspace README around CAD") was docs-only. Its head commit has exactly one
check-run — `automerge: skipped` — and **no `test` at all**. It was merged at
16:07 by `lorenzoliuzzo` via admin bypass, because nothing else could have
merged it. **The current `main` of the fleet's own operations repo carries zero
verification.**

This is not a `my-fleet` quirk. **MEASURED: 20 active repos ship `paths-ignore`
in `ci.yml`, and every single one of them requires `test`** — the overlap is
100%, so there is no repo where this setting is currently harmless. They include
`my-template`, which propagates the defect to every repo scaffolded from it;
`my-coder`, the worker that is supposed to open these PRs; and `my-raytracer`,
the one repo with a proven autonomous track record. (A further 14 archived repos
carry it too, which is how a naive local grep returns 36.)

And it defeats the gate by construction. `accept.py:308` maps any check state
that is not `pass`/`fail` to `None`; `accept.py:146` refuses to accept when any
check is `None`. So a docs-only PR is not merely un-merged, it is
**un-*acceptable*** — `myfleet.accept` must refuse it forever, on correct
reasoning, from correct evidence. CAD cannot autonomously land a documentation
change in any of the 20 repos that carry this setting.

The fix is GitHub's documented one and it is small: drop `paths-ignore`, and
instead short-circuit the expensive steps inside a job that always reports. A
required check must always *report*; only its *work* may be skipped.

This is the same shape as [`my-fleet#52`][52] ("CI never runs on a stacked PR,
so it can never satisfy branch protection"). **They are one bug with two
triggers — stacked base branches and ignored paths.**

[`my-fleet#82`][82] merged during this review and fixed the *stacked* trigger by
dropping the `branches:` filter from `pull_request`. It deliberately left
`paths-ignore` in place, so the docs-only trigger is untouched and F1 stands in
full. That is a clean demonstration of why the two should be fixed together:
half the bug was removed by a fix whose own commit message correctly describes
the general principle — *"not a failure, an absence"* — and then leaves the other
absence sitting two lines above it in the same `on:` block.

### F2 — The test suite writes to the production ledger, so the fleet's own telemetry is unreadable

**MEASURED.** `.my-fleet/ledger.jsonl` holds 228 entries: 92 on 2026-07-07, 11
on 2026-07-08, and 150 "today". The 150 span 71 minutes, but **144 of the 149
gaps between them are under 5 seconds and 142 are sub-second**. Only ~5 gaps
(218s, 330s, 456s, 1562s, 1693s) are consistent with a timer. All 150 are
`fleet_cycle` / `bookkeeping` / `ok`.

This is [`my-fleet#74`][74] — "PR #57's new `fleet_cycle` tests write to the
production ledger in a normal checkout" — already filed and still open.

The severity is not the junk rows. It is that **the ledger is the instrument
every review, every dashboard, and the dead-man's switch all read to answer "is
the fleet alive?"** An instrument that reads `ok` 150 times because its own test
suite ran is worse than one that reads nothing: it manufactures exactly the
false green the CAD gate was built to eliminate. A reviewer glancing at today's
ledger would conclude the fleet is running. It has not dispatched in 67 days.

`#74` carries **no `lane` or `prio` label**, so the ranker cannot schedule it
(see F3).

### F3 — The transferred backlog is invisible to the queue

**MEASURED.** `my-fleet` has 17 open issues. Eleven carry `lane:kernel` plus a
priority. **Six do not: #64, #65, #66, #67, #68, #69** — the ASK-channel EPIC
and its children, transferred wholesale from `fleet-dispatch` during its
wind-down — plus `#74` from F2. Seven of 17 are unlabelled.

`mythings.labels.sort_key` ranks on `lane` then `prio`. An issue with neither
does not rank; it sits below everything forever. So the fleet's human-in-the-loop
EPIC, and the bug corrupting its telemetry, are both structurally unreachable by
the machine built to work the backlog.

One piece of good news, since it was an open worry from the wind-down:
**GitHub remapped the cross-references correctly on transfer.** `#64`'s body now
points at `#65`–`#69`, its real siblings. **OBSERVED:** one dangling reference
survives — `#99`, which does not exist in `my-fleet` (highest is `#82`) and is
presumably a `my-telegram-bot` number from the original text.

**Labelling seven issues is ten minutes of work and is the highest
leverage-per-minute item in this review.**

### F4 — Backlog growth still outruns drain, and it is concentrated

218 open issues org-wide, up from a July baseline that was already called
unsustainable. But the distribution matters more than the total:

| Repo | Open | Reading |
|---|---|---|
| `study` | 72 | Course content, not engineering debt. Different queue. |
| `my-idea` | 63 | Triage inbox by design — this is the tool working. |
| `my-fleet` | 17 | **Real kernel debt.** |
| `my-things-core` | 10 | Real, and the contracts everything depends on. |
| `my-coder` | 7 | Real, in the worker that does the building. |
| everything else | ≤6 each | Long tail. |

**Excluding `study` and `my-idea`, the org carries 83 open issues, and 34 of them
sit in the four kernel repos.** That is a tractable number. The headline 218 has
been scaring successive reviews into thinking the backlog is hopeless; it is not,
it is just badly aggregated.

Of 33 open PRs, **12 are Dependabot and 5 are `study` research PRs**, leaving 16
substantive. Three are old implementation PRs that have now waited two months
([`my-equations#2`][eq2], [`my-tables#2`][tb2], from 2026-07-12 — the day of the
*first* review).

### F5 — `goal/cad-foundation` is the one thing working as designed

**MEASURED:** 15 closed, 9 open. The nine open are correctly labelled, correctly
sized, and all nine are `state:blocked` — they are the second phase (`Foreman`,
lane allocation, phase-scoped decomposition, the reporter's burn-down), gated
behind the first. That is a milestone behaving like a plan rather than a wish
list, and it is the clearest evidence the CAD rebuild was the right call.

### F6 — August's diagnosis was right and got fixed; it just was not sufficient

August blamed the stall on (1) an uninstalled scheduler and (2) saturated human
merge authority. Both were addressed: the Pi timer chain was traced and repaired,
and the merge gate plus ASK channel now let a human approve from a phone.
Neither unblocked dispatch, because **F1 and F2 sit downstream of both.** A
scheduler that fires into a gate that cannot accept, writing to a ledger that
cannot be read, produces exactly what we see: heartbeats, `ok`, and no work.

This is the recurring lesson, now three reviews deep: **the fleet's failures are
never capability failures. They are always one small mechanism that reports
success while doing nothing.**

## 5. Plan of action

### Immediate (hours) — mechanical, unblocks everything downstream

1. **Label the seven unlabelled `my-fleet` issues** (#64–#69, #74). Ten minutes.
   Nothing else in this list can be scheduled by the machine until this is done.
2. **Fix `#74`** — point the `fleet_cycle` tests at a tmp ledger. Until this
   lands, no measurement of fleet liveness means anything, including the
   dead-man's switch.
3. **Truncate or annotate the polluted ledger rows** so the 150 synthetic `ok`s
   do not read as history in the next review.

### Short term (≤2 weeks) — ordered by leverage

4. **Fix F1 in `my-template` first**, then fan out. Replace `paths-ignore` with
   an always-reporting `test` job that skips its expensive steps internally.
   [`my-fleet#82`][82] already closed the stacked-PR half of the same bug; this
   is the remaining half.
5. **Re-run the fan-out check afterwards**: 20 active repos carry the defect. The fix is
   mechanical and identical in each, which makes it an ideal first real
   `my-coder` batch — and a genuine end-to-end test of CAD on safe, reversible,
   high-volume work.
6. **Then let dispatch run.** With F1 and F2 fixed, the gate can accept, the
   ledger can be trusted, and the queue can rank. That is the whole precondition
   list.
7. **Decide `my-office` and `my-city`.** They are deleted from GitHub and exist
   only as local directories — push them back or delete the directories, but
   stop carrying two tools in a state where one `rm` ends them.
8. **Resolve the three two-month-old implementation PRs** ([`my-equations#2`][eq2],
   [`my-tables#2`][tb2], [`my-server#9`][sv9]) — merge or close, but stop
   carrying them.

### Mid term (1–2 months)

9. **Unblock the nine `goal/cad-foundation` items** in dependency order, starting
   with the Foreman ([`my-fleet#29`][29]).
10. **Give the ledger a schema check in CI.** F2 was findable only by computing a
    gap histogram by hand. A ledger that can be silently poisoned by a test run
    needs the same "is this evidence real?" treatment the merge gate got.
11. **Pin `my-things-core`.** `ci.yml:34-42` documents at length why every repo
    floats on `@main` — core's only tag is `v1.0.0` while `pyproject` says
    `1.2.0`, and its CHANGELOG carries two different `[1.2.0]` entries. Every
    repo in the org is therefore CI-coupled to core's unreleased `main`. Tag
    core and pin it.

### Strategic

The fleet has now been built three times over and run once, for one day, in
July. The capability is not in question — `my-raytracer`'s 13 autonomous
sessions settled that in August and nothing since has contradicted it. **What is
in question is whether anyone will run it before building the next layer on top
of it.** The `goal/cad-foundation` second phase (Foreman, lane allocation,
phase-scoped decomposition) is a further layer of machinery above a loop that
has never completed a full cycle unattended.

**Recommendation: do not start phase two until dispatch has run unattended for
seven consecutive days.** Not as process theatre — as the only way to discover
the next F1, which will also look like a green `ok` and also be a single line in
a YAML file.
