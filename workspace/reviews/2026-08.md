## 1. TL;DR

**July's homework got done. Then nobody sat the exam.**

Of July's ten short-term action items, **seven shipped, two are partial, and one
was built and never installed.** The single most-wrong thing in July — the
`EngineRequest.context` drop that silently broke `my-guide.wish()` — is fixed
*and* regression-guarded by a real contract test. Identity separation is
enforced. Secrets are redacted from transcripts and ledger records. The ASK
daemon is re-preflighted every loop iteration. `fleet_cycle` honours HALT.
Dispatch fetches `origin/main` first. Branch protection went **30/41 → 48/56**.
`fleet_dispatch` was rearchitected to dispatch through `my-coder` (v2.0.0) and
the cycle now runs off `my-pipeline`'s declarative graph. This is a serious
execution record against a review.

And yet **the fleet has been completely idle for 25 days.** The shared runtime
ledger's last entry is 2026-07-30. `fleet_dispatch` — the autonomous loop the
whole system exists to run — has not written since **2026-07-08, 47 days ago**,
the exact same eight sessions July reported. **Thirty-seven of 54 local repos
have had zero commits** since the last review.

The cause is now precisely diagnosable, which it was not in July, and it is not
what July guessed. It is not the caps, the guard, the identity model, or the ASK
channel — those were the fixes, and they landed. It is two things, both trivial
to state:

1. **The scheduler exists as a file and was never installed.**
   `my-fleet/systemd/fleet-bookkeeping.timer` is committed, correct, and absent
   from `systemctl list-timers`, from `--user`, and from `/etc/systemd/system`.
2. **Human merge authority is saturated.** 26 PRs are open; the green,
   mergeable, ready-for-review ones have waited **six weeks**, including two
   tools' core implementations.

The single most-right thing this cycle is **my-raytracer**: on 2026-07-19,
thirteen `my-coder` sessions autonomously shipped a backend-agnostic core seam,
a wavefront integrator, MIS, GGX and dielectric BSDFs, triangle meshes, inverse
rendering, and 3D Gaussian splatting — ~80 commits, every one a reviewed PR.
**That is the thesis working, unattended, on genuinely hard graphics code.** It
has not happened since.

July's verdict was *"freeze the tool count and harden."* The hardening happened;
the freeze did not (`my-cartographer`, `my-embedder` are new). **This review's
verdict is narrower: stop building and start _running_.** The constraint is no
longer capability, safety, or tool count. It is that nothing is switched on.

## 3. Findings

### F1 — Human merge authority is the fleet's single point of failure

**MEASURED. Critical.**

The design is explicit and right in principle: *"Never merge a PR yourself…
a human always merges."* In practice it converts one person's attention into
the throughput ceiling for 56 repos. Live state:

| PR | Checks | Mergeable | Age |
|---|---|---|---|
| `my-equations#2` — *core implementation* | ✅ SUCCESS | MERGEABLE | **6 weeks** |
| `my-office#1` — *core implementation* | ✅ SUCCESS | MERGEABLE | 5 weeks |
| `my-site#6` | ✅ SUCCESS | MERGEABLE | 3 weeks |
| `my-things-core#134`, `my-fleet#17` | ✅ SUCCESS | MERGEABLE | 4–5 weeks |
| **17 × Dependabot `setup-python` 6→7** | ✅ SUCCESS | MERGEABLE | 4 weeks |

The fleet is *generating* correct, green, reviewed work and cannot *land* it.
`my-equations` and `my-tables` are, on paper, unimplemented tools — their
implementations have been sitting in an open PR since 2026-07-12.

**Second-order effect:** `my-tables#2`, `my-coder#16`, and `my-server#9` are
**RED and have been for weeks with nobody re-driving them.** Once a worker
exits, nothing watches its CI. A failed PR is indistinguishable from a waiting
one until a human opens it.

The fix is *not* to weaken the invariant. It is to **separate risk classes**: a
Dependabot patch bump with green CI does not need the same human as a
core-contract change. See §6.

### F2 — The scheduler was built and never installed

**MEASURED. Critical. This is the whole idleness story.**

July's action item #10 shipped on 2026-07-12 (`my-fleet` commit *"Add a daily
systemd timer for the bookkeeping half-cycle"*). The unit files are present and
correct:

```
my-fleet/systemd/fleet-bookkeeping.timer   # OnCalendar=daily, Persistent=true
my-fleet/systemd/fleet-bookkeeping.service
```

They are **not installed anywhere**: absent from `systemctl list-timers --all`,
from `systemctl --user list-unit-files`, and from `/etc/systemd/system/`.

`my-fleet/README.md` states `fleet_cycle --loop` is *"meant for an always-on
host, not an interactive session."* **There is no always-on host.**
`my-things-core/docs/ARCHITECTURE.md` says *"No scheduler/daemon — GitHub
Actions `schedule:` is the conductor,"* but the dispatch loop needs a real
machine with credentials, and Actions was never wired to drive it. The two
documents describe two different conductors and neither exists.

This is a `systemctl enable --now` away from being solved.

### F3 — "Mechanism without adoption" is the fleet's signature failure class

**MEASURED. This generalises July's finding about the GitHub App.**

| Mechanism | Built | Adopted |
|---|---|---|
| `EngineRequest.context` contract | ✅ | ✅ **— because a contract test forces it** |
| `MeteredEngine` (`kind=engine_usage`) | ✅ `engine.py:299` | ❌ **1 of ~50 tools** |
| systemd bookkeeping timer | ✅ | ❌ never installed (F2) |
| GitHub App identity | ✅ + now enforced choice (#55) | ⚠️ partial |
| Branch-protection audit in the cycle | ❌ | ❌ (July item #1, half-done) |

The one that stuck is the one with a test behind it
([`test_context_is_never_transmitted_to_the_model`](my-things-core/tests/test_engine.py:406)).
**Mechanisms adopted by test are adopted; mechanisms adopted by documentation
are not.** This is the most actionable structural lesson in this review, and it
predicts which of §7's items will actually take.

Concretely: per-tool Engine spend remains unmeasurable, which is precisely what
July's Q5 asked for. `MeteredEngine` is not the answer — **instrumenting
`ClaudeCLIEngine` once, inside core, is**, because it removes the adoption step
entirely.

### F4 — Two repos never completed genesis

**MEASURED.**

`my-image-processor` (default branch `feat/genesis-scaffold`) and
`my-manim-editor` (default branch `build/render-tool`) have no `main`. They are
therefore invisible to every branch-protection audit, every CI-on-main check,
and `my-dashboard`'s shelving. Stuck since 2026-07-12.

### F5 — `my-dashboard` — the fleet's own status page — is red

**MEASURED.**

Failing on `main` since **2026-07-20** (*"Adopt the v1 release contract:
RELEASE.md, CHANGELOG…"*). The one tool whose job is to report fleet health has
been broken for five weeks and nothing announced it. Structurally identical to a
red CI nobody watches: **a failure that does not announce itself is a failure
that does not exist** until someone goes looking.

### F6 — `my-fleet` itself is unprotected

**MEASURED.**

Eight repos lack branch protection: `.github`, `typst-templates`,
`typst-personal-docs`, `study`, **`my-fleet`**, `my-designer`,
`my-cartographer`, `my-embedder`.

Most are benign. **`my-fleet` is not** — it is the driver that dispatches every
worker and holds the spend caps and the kill switch. Also note the new-repo
pattern: `my-cartographer` and `my-embedder` were created after July's
protection sweep and immediately drifted unprotected, which is exactly the
recurrence July's item #1 (*"audit protection in the cycle"*) was meant to
prevent. **That half of the item was never built** — no protection check exists
in `my-fleet` or `my-dashboard`.

### F7 — Backlog accumulates faster than it drains; `TODO.md` is stale

**MEASURED.**

171 open issues, **62 in `my-idea` alone** — an idea-generation tool filling a
backlog nothing consumes. Meanwhile the curated root `TODO.md` still lists
MySearcher, MyScaffolder, and MyCoder under *"Later / tool-build"*. All three
exist; **`my-coder` is the most productive tool in the fleet.** `my-todo`'s
output is only as fresh as the cycle that regenerates it, and the cycle does not
run (F2) — instrument rot, exactly the class July's item #10 was aimed at.

### F8 — The kernel/inventory ratio has not improved

**MEASURED. Strategic.**

Six repos were added against July's explicit *"freeze the tool count"*
(`my-cartographer`, `my-embedder`, `my-office`, `my-city`, `my-architect`,
`my-pipeline` — the last two are arguably kernel). The shelf band still holds
~35 tools at 250–650 LOC.

The nuance worth recording: **`my-raytracer` is the counter-example that
matters.** It is the largest single tool (3,631 LOC) and it got that way by
being *fed to the loop*, not by being scaffolded. The fleet's demonstrated
growth mechanism works; it is simply not being used.

## 5. What is genuinely strong

The findings above are about *operation*, not *construction*. The engineering
quality is high and should be said plainly:

- **The five-contract SDK is a real abstraction.** `ledger`/`policy`/`engine`/
  `github`/`isolation` are the right seams, and making `Engine` the *single* LLM
  call site anywhere in the system is a genuinely good idea that most agent
  frameworks get wrong.
- **`NoopEngine`-first testability.** Every tool is end-to-end testable at zero
  token cost — 2,250 tests over 37k LOC.
- **The fail-closed instincts are correct throughout.** `reserve_engine_call`'s
  guard-in-the-`WHERE`-clause (the read-then-write race analysis in
  ARCHITECTURE.md is genuinely excellent — a naive version oversells ~96 calls
  against a quota of 50), deny-on-timeout in `TelegramPolicy`, and HALT as a
  marker file that stops the *next* session rather than corrupting a running
  one.
- **Draft → ready → green → merge, GitHub-enforced** on 48 repos is a better
  gate than most production teams run.
- **my-raytracer proves the thesis.** Everything else in this document is an
  operations problem sitting on top of a working machine.

## 6. Open-source tools worth adopting

Surveyed 2026-08-24, ordered by leverage against §3, not by popularity.

### Tier 1 — directly unblocks the stall

**[Kodiak](https://github.com/chdsbd/kodiak) or GitHub's native merge queue → F1.**
Kodiak is MIT and self-hostable and does exactly the missing step: keep a PR
current with `main`, wait for green, merge in order. Configure it for the
*low-risk classes only* — Dependabot patch/minor bumps, `my-docs` sync,
`my-changelogger` updates — leaving core-contract and `my-coder` PRs for a
human. That drains 17 of 26 open PRs without weakening the invariant where it
carries weight. GitHub's native merge queue is free and simpler if Kodiak's
auto-update behaviour isn't needed.

**[Renovate](https://github.com/renovatebot/renovate) replacing Dependabot → F1.**
Self-hostable, MIT. The decisive feature is **grouping**: one PR reading "bump
`setup-python` across 17 repos" instead of 17 identical PRs. With automerge
rules for CI-only changes, the dependency-maintenance load essentially
disappears. For a 56-repo org this is the single highest-ratio tool in this
list.

**A scheduler → F2.** Three weights:
- *Lightest, and what F2 actually calls for:* `systemctl enable --now` the timer
  that already exists, on an always-on host. Zero new stack.
- *Middle:* [Windmill](https://www.windmill.dev/) — AGPL, self-hosted,
  Python-native, benchmarked the fastest self-hostable generic workflow engine.
  Gives schedules, retries, a UI, and **approval steps** that map cleanly onto
  the ASK channel.
- *Heaviest:* [Temporal](https://temporal.io/) — durable execution that survives
  a crash mid-workflow. Correct if `fleet_cycle`'s 8 steps need to be
  individually resumable; overkill otherwise.

**[Langfuse](https://github.com/langfuse/langfuse) → F3.**
Self-hosted, OpenTelemetry-based, per-call cost tracking. This is the honest
answer to `MeteredEngine`'s 1-of-50 adoption: instrument `ClaudeCLIEngine`
**once** inside `my-things-core` and every tool is metered for free — mechanism
adopted at the seam rather than by convention, which F3 says is the only kind
that sticks. [Helicone](https://github.com/Helicone/helicone) is the
lower-effort proxy-based alternative;
[OpenLLMetry](https://github.com/traceloop/openllmetry) if you'd rather emit
OTel and choose a backend later.

### Tier 2 — closes the still-open safety TODOs

**[OSV-Scanner](https://github.com/google/osv-scanner) +
[pip-audit](https://github.com/pypa/pip-audit) → `fleet-dispatch#6`**
(dependency-vulnerability scanning, still open). Google/PyPA-maintained, both
trivially added to the shared workflow template.

**[gitleaks](https://github.com/gitleaks/gitleaks) → `fleet-dispatch#9`**
(secret-leak check on ledger/PR content). Single binary, offline, works in
pre-commit and CI. Note this *hardens an instinct already present* —
`my-fleet` already redacts credential-shaped text (#54) — rather than
introducing a new concern. [TruffleHog](https://github.com/trufflesecurity/trufflehog)
for deep history scans, where live-credential verification separates real
emergencies from noise.

**[zizmor](https://github.com/woodruffw/zizmor) → fleet-wide.**
Audits GitHub Actions workflows for supply-chain misconfiguration; adopted by
PyPI after their own incident. With 56 repos sharing a vendored workflow
template, **one misconfiguration is 56 misconfigurations** — the blast radius
argument is stronger here than for a normal org.

**[Open Policy Agent](https://github.com/open-policy-agent/opa) or
[Cedar](https://github.com/cedar-policy/cedar) → `my-guard`.**
Only if `my-guard` should grow past 334 LOC. Real policy language, testable
rules, decision logs. **Trade-off:** adds a non-Python dependency against the
dependency-free-runtime principle, and `my-guard`'s thinness is arguably a
feature. Recommendation: **read OPA's decision-log design; do not necessarily
adopt OPA.**

### Tier 3 — read, probably do not adopt

**[OpenHands](https://github.com/All-Hands-AI/OpenHands)** — MIT, ~70k stars,
72.8% on SWE-bench Verified with Sonnet 4.5. `my-coder`'s direct competitor and
genuinely strong. But `my-coder` demonstrably works (my-raytracer), and adopting
OpenHands would replace the one component whose quality is actually proven.
**Read its sandboxed-runtime design; keep the worker.**

**[microsandbox](https://github.com/microsandbox/microsandbox) /
[E2B](https://github.com/e2b-dev/E2B) / gVisor / Firecracker → `isolation`.**
`Workspace` uses git worktrees, which isolate *the tree being edited* but not
*the process*. A worker running `claude -p` with tool access has the host's
blast radius. MicroVM isolation (sub-200 ms boot) would make the sandbox real.
**Caveat:** Daytona's OSS repo has been unmaintained since June 2026 — not that
one.

**[Paperclip](https://github.com/paperclipai/paperclip)** — MIT, Node/React/
Postgres, agent org chart + heartbeats + budgets + approvals UI. Assessed
separately; the short version after measuring this fleet is that **paperclip
solves F1 and F2 and nothing else MyThingsLab needs.** Its approvals UX and
cumulative-budget-with-auto-pause are genuinely ahead of `my-dashboard`, but
adopting it means running a competitor's stack to obtain a scheduler and a merge
gate that systemd + Kodiak provide for free. **Mine it for roadmap ideas; do not
adopt it.**
