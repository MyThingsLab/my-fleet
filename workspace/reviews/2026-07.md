# MyThingsLab — full-ecosystem review, 2026-07-12

_Read-only review session. Every claim is tagged **MEASURED** (I ran it in this
session), **OBSERVED** (I read it in code/docs/ledgers), or **HYPOTHESIS**
(inferred, with the test that would confirm it). One caveat up front: the
session sandbox refused to run `fleet_cycle.py` even in dry-run mode, so the
full-cycle instrument was assessed from code + ledgers, not exercised._

---

## 1. TL;DR

The fleet is a well-built **kernel of ~10–12 living tools wrapped in ~30 repos
of shelf inventory**, and the autonomous loop it was built for has effectively
never run: the dispatch ledger records **8 billed worker sessions, all on July
7–8, $9.50 total, zero since** — everything after that was built by interactive
sessions. The single most-wrong thing is that the **one non-deterministic seam
is the least-guarded part of the system**: `EngineRequest.context` is still
silently dropped by the real engine, and `my-guide`'s core call ships broken
because of it, invisible to its green CI — exactly the failure class the
deterministic-first paradigm is structurally blind to. The single most-right
thing is the gate discipline: every one of 41 mains is green, `HARNESS.md` has
zero drift on any `origin/main`, `_compat` reconciles clean, and
`fleet_dispatch.py` is genuinely hardened (per-session $3/40-turn/30-min caps,
$20/day ceiling, HALT marker, honest outcome vocabulary, resume-not-restart).
Safety issues #6–#10 are closed on paper but two closures are mechanism-without-
adoption: the GitHub App identity exists as opt-in flags while the default
credential is still the personal PAT with full `repo` scope over *everything*
the owner can touch, and 11 repos — including `my-template` itself — have no
branch protection. "Leave it running for a week" is **weeks away, not months**:
the loop, caps, kill switch, and resume logic exist; what's missing is enforced
identity separation, an ASK channel that survives a daemon death, metering for
the non-dispatch Engine spend, and one supervised multi-day run to prove the
economics. Freeze the tool count and harden — the census below says growth is
currently manufacturing inventory, not capability.

## 3. Findings

### Q2 — What we are handling badly (failure classes)

**F2.1 — Instrument rot is systemic; the root cause is that the loop that
would keep instruments fresh isn't running.** (MEASURED)
- `TODO.md` still lists safety issues #6/#7/#8/#10 under "Now"; all four were
  closed 2026-07-10 (`gh issue view` per issue). `mytodo` last ran 07-08.
- `.claude/HANDOFF.md` covers 8 of 41 repos and reports "_repo dir not found
  locally_" for the SDK, because `.claude/scripts/handoff.sh` hard-codes
  `REPOS=(mythings-core …)` — the pre-rename name — instead of discovering
  checkouts the way `fleet_cycle.tool_repos()` does (handoff.sh:14).
- The docs site is 10/38 pages; dashboard stale since 07-10.
- `myorchestrator next --count 5` returns **five `scaffold:` candidates, all
  undispatchable** (MyScaffolder doesn't exist), so the instrument's headline
  answer is permanently one the fleet cannot act on; `fleet_dispatch` works
  around it by overfetching (fleet_dispatch.py:1191).
- Root cause: every instrument is refresh-on-run, and nothing runs them.
- Cost: any resumed session (human or agent) orients from wrong state; the
  fleet's self-description claim fails its own test.
- Smallest structural fix: (a) replace handoff.sh's list with the
  `*/pyproject.toml` glob; (b) schedule the **bookkeeping half** of
  `fleet_cycle.py` (no `--dispatch-execute`) as a timer so
  todo/docs/dashboard/projector/reporter stay fresh without spawning workers.

**F2.2 — Stale-workspace dispatch: workers can start from an old `main`.**
(MEASURED for staleness; OBSERVED for the mechanism)
13 local checkouts had a `HARNESS.md` differing from canonical — all 13 were
merely *stale local checkouts* (their `origin/main` is clean). But
`mythings.isolation.Workspace` creates worktrees from the **local** ref
(`worktree add --detach <base_ref>`, isolation.py:35, no fetch), and
`fleet_dispatch._dispatch_one` fetches only when resuming a prior branch
(fleet_dispatch.py:803-806) — a fresh dispatch bases on local `main`, days old.
`fleet_cycle` steps 4–5 likewise run `mytester`/`mychangelogger` against the
stale checkouts. Smallest fix: `git fetch origin` + base `origin/main` in
`_dispatch_one` for fresh dispatches, and a fetch sweep at the top of each
cycle iteration. The harness rule "never trust a local checkout" (harness.md:20)
is currently advisory for the *drivers themselves*. Related: the deployment
wrapper `run_fleet_cycle.sh:11` defaults to `~/.claude-personal,~/.claude-work`,
not the documented account pair — stale defaults in the same class.

**F2.3 — Ship-then-fix at genesis: the lesson is still tribal, not a gate.**
(OBSERVED) harness.md:30-32 tells the agent to run `GITHUB_ACTIONS=true pytest`
with core@main before shipping — advisory text; nothing in CONVENTIONS.md's
Rule→Gate table backs it mechanically, and the repair-PR history (my-planner#1,
my-projector#1, the five repos scaffolded from a stale template patched
2026-07-08) is the bill. Smallest fix: a `my-template` `scripts/preflight.sh`
(or pre-push hook) that runs exactly that command, so the gate ships with
every scaffold.

**F2.4 — Coordination debt has moved, not gone.** (MEASURED) Open PRs
org-wide: **0** — the human is keeping up with merges (impressive, and partly
because the loop is idle). The queue is now decisions: 7 open `needs-decision`
issues, 14 designed-only tools, and fleet-dispatch#42/#43/#46 all propose
Telegram-based supervision. Where the human is the bottleneck on **merges and
repo creation**, that is correct by design; where it's **stale instruments
telling the human wrong things** (F2.1), it's just unfinished tooling.

**F2.5 — Root-repo governance: largely fixed, one real gap left.**
(MEASURED) fleet-dispatch has had CI (ruff + pytest behind a required `test`
check) since 2026-07-08 and branch protection — the prior-session claim is
stale. The real remainder: **11 repos have no branch protection** —
my-archivist, my-coder, my-docs, my-idea, my-librarian, my-presentation,
my-raytracer, my-site, my-template, my-typster, mythingslab.github.io — and
`my-template` is the one every future tool inherits its expectations from.
Protection is applied manually per repo (issue #29 open for auto-audit); the
newest repos prove manual doesn't stick.

### Q3 — Safe continuous autonomy: the gap analysis

**The five safety issues** (all states verified via `gh issue view`):
- **#6 dep-vuln scanning — closed 07-10, real but warn-only.** `pip-audit` in
  template CI with `continue-on-error: true` + Dependabot
  (CONVENTIONS.md:126-146). Deliberate; needs the promised flip to hard-fail
  after triage.
- **#7 GitHub App identity — closed 07-10 as mechanism, not adoption.**
  `--app-id/--app-installation-id/--app-private-key` exist
  (fleet_dispatch.py:1060-1141, `mythings.github.github_app_token`), but the
  default run — and every `gh` call in every tool — uses the ambient personal
  token. **MEASURED:** `gh auth status` shows `lorenzoliuzzo` with scopes
  `repo, workflow, project, admin:public_key, gist, read:org`. A misbehaving
  worker (`Bash(git *)`, `Bash(gh pr create*)`, `Bash(gh issue create*)` are
  allowlisted, fleet_dispatch.py:79-118) can therefore push branches and open
  PRs/issues **on any repo the personal account can write to — including
  non-MyThingsLab ventures.** The repo-isolation invariant is enforced by
  convention, not credential. Issue #30 (enforce identity separation) is open
  and is the real closing item.
- **#8 spend/turn cap — closed 07-10, genuinely.** Per-session
  `--max-budget-usd 3`, `--max-turns 40`, `--session-timeout-s 1800`, plus a
  `--max-daily-usd 20` UTC-day ceiling enforced *before* launch
  (fleet_dispatch.py:1258-1270). Gap: these bound **dispatch** only — the
  cycle's other billed steps (researcher briefs, any `--engine claude-cli`
  tool call) are unbounded and unmetered (see Q5).
- **#9 secret-leak on ledger/PR content — still open, half-built.**
  `mythings._secrets` scans diffs + PR bodies in CI (CONVENTIONS.md:101-124);
  nothing scans **ledger content or worker transcripts**, which is what the
  issue asks. Transcripts land verbatim in `.fleet-dispatch/transcripts/`.
- **#10 kill switch — closed 07-10, with one hole.** HALT marker + `--abort`/
  `--clear-halt` (fleet_dispatch.py:71, 1073-1088, 1110-1121); `fleet_cycle`'s
  dispatch step inherits it. **The hole (OBSERVED):** `fleet_cycle.py` never
  checks the marker itself, so with `--execute --engine claude-cli` the
  briefs, tester, reporter-summarize etc. keep making billed Engine calls
  after a HALT. The critical-issue soft halt has the same shape: checked only
  in `fleet_dispatch.main` (fleet_dispatch.py:1166).

**Blast radius (worst single cycle, today's credentials):** spend is bounded
($20/day dispatch + unmetered-but-small Engine steps); **spam/exposure is not**
— full-`repo`-scope personal PAT across the owner's entire GitHub, 11
unprotected mains (a worker *could* push directly to `my-template`'s main and
poison every future scaffold), transcripts/ledger unscanned for leaked
secrets. Branch protection does hold on the 30 protected repos (PR + green
`test` required, no direct/force push).

**ASK channel end-to-end** (OBSERVED, code-traced): the design is sound —
absolute ledger path threaded (fleet_ask.py:32; the worktree-cwd trap is
documented and closed), fail-closed total (`SubprocessAsk` maps every failure
mode — missing binary, crash, timeout, non-zero exit — to DENY, ask.py:46-79;
Guard escalates only ASK, never widens an ALLOW/DENY, guard.py:63-75).
Remaining failure modes:
1. **Daemon death mid-loop.** `daemon_is_running()` (fleet_ask.py:49-84) is
   checked once, when the channel is armed. In `--loop`, a daemon that dies on
   day 2 turns every ASK into a 300s block + DENY — "slower than no channel
   and just as closed," the exact state the preflight exists to prevent. No
   re-preflight per iteration, no skip-and-report degradation.
2. **The daemon has never run on this host.** MEASURED:
   `my-telegram-bot/.mythings/ledger.jsonl` does not exist, so `--ask-human`
   would refuse to arm (fleet_ask.py:114-119). Fail-closed works; it also
   means the whole path is unexercised outside the one CI e2e test
   (dev-ledger 2026-07-07, workflow run 28840280628).
3. **Timeout starvation** is real but self-limiting per action (300s each,
   serialized). Worth a ledger counter of ask-timeouts per cycle so thrash is
   visible; not a blocker.

**Unattended failure recovery** (OBSERVED): resume/recover is genuinely good —
durable branches pushed even on failure, transcripts kept, `deferred`
(transient) excluded from the 3-attempt cap, `needs_human` recorded once and
not re-counted (fleet_dispatch.py:533-639, 1232-1249). When a whole class goes
`needs_human` the loop idles politely (exponential backoff to 30 min,
fleet_cycle.py:276-334). **But nothing guarantees a human finds out:**
`needs_human` reaches a human only via `mytelegrambot notify` (cycle step 10,
`--execute` only) — the notify path whose daemon has never run here. An
unattended week with a dead bot is a silent week.

**Observability — the 48h reconstruction test (MEASURED):** from
`.fleet-dispatch/ledger.jsonl` alone I answered "what did the last 5 dispatched
sessions cost and produce" precisely: mythings-core#14 $1.79/77t → PR #24;
mythings-core#17 two $0 aborted runs, then $1.50/63t → PR #25; my-uni#2
$2.88/103t → needs_review (branch pushed, no PR opened). Per-session cost,
tokens, cache stats, denial count, transcript path, outcome, final message —
all present. **Dispatch observability: pass. Everything else: fail** —
per-tool Engine calls write no cost anywhere, so a 48h loop's *total* spend is
not reconstructable.

**Ranked: what stands between today and "leave it running for a week"**
1. **Identity separation enforced, not optional** — dispatch under the GitHub
   App so the worst case is scoped to org repos. *Acceptance: a worker's `gh`
   identity inside a session is the App installation, and a PAT-only run
   refuses to start without an explicit override flag.*
2. **Branch protection on all 41 repos + drift audit in the cycle** (#29).
   *Acceptance: a cycle/dashboard check flags any unprotected repo; count 0.*
3. **ASK-channel liveness across the loop** — re-run `daemon_is_running()`
   each iteration; on failure, disarm + ledger + report instead of
   300s-denying everything. *Acceptance: kill the daemon mid-loop in a test;
   the next iteration logs the degradation and ASKs fail fast.*
4. **Meter every Engine call** (see Q5). *Acceptance: after one `--execute`
   cycle, `kind=engine_usage` entries sum to a nonzero total covering briefs
   + summaries, and `--max-cycle-budget-usd` counts them.*
5. **HALT + critical-halt gate the whole cycle**, not just dispatch.
   *Acceptance: touch HALT mid-loop; the next iteration runs no billed step.*
6. **needs_human → guaranteed human delivery** — notify-path health check +
   a daily digest even when nothing dispatched. *Acceptance: a needs_human
   entry produces a Telegram message within one cycle, verified live.*
7. **Fetch-before-dispatch** (F2.2). *Acceptance: dispatch with local main
   deliberately 2 commits behind; the worker's worktree contains both.*
8. **Transcript/ledger secret scan** (#9). *Acceptance: a planted fake token
   in a test transcript trips the scan before the file is written.*
Then one supervised 72h `--loop` run with `--max-cycle-budget-usd` set is the
graduation exam for the week-long unattended target.

### Q4 — Is the harness thesis holding?

**The one-Engine-call invariant is real, with honest edge cases.** (MEASURED)
37 `EngineRequest(` call sites across 33 tools; 29 tools have exactly one.
The four with two (my-researcher, my-professor, my-glossary, my-textbook) are
one-call-per-*command* (e.g. brief vs study-path), which respects the spirit;
nothing resembles a smuggled multi-call agent loop, and no LLM call exists
outside the seam. One inversion risk to watch: `Guard._judge` (guard.py:77-92)
puts an Engine call inside the *safety* path — opt-in, fail-safe to ASK,
never overriding an explicit rule, which is the right shape, but it is the one
place a cheap-model default must never land.

**Does determinism buy what it promises? Incidents both ways.**
- *Caught by gates (MEASURED/OBSERVED):* the harness-v2 re-vendor swept every
  repo and today **zero** repos drift on `origin/main` (I hashed every
  `HARNESS.md` against canonical) — the drift test does its job at PR time.
  `_compat` went from "5 unmet claims" to 0 errors by **building** the claimed
  core methods (`diff`, `repo_list`, `list_labels`, `repo_create`,
  `get_file_contents` all exist, github.py:220-257) — gates ahead of reality,
  then reconciled. The paradigm working as designed.
- *Missed by gates (OBSERVED):* the context-drop bug (below) shipped through
  green CI everywhere, because NoopEngine-based tests cannot see what the real
  backend ignores. A monolithic agent design would not have had this
  *particular* bug — the paradigm's blind spot is precisely its one seam.

**The engine-boundary defects — current status (MEASURED against
`origin/main` of my-things-core):**
- Fence-stripping: **fixed.** `_strip_code_fence` at engine.py:54-59, applied
  in `run()` at engine.py:94.
- Context drop: **still open.** `ClaudeCLIEngine.run` serializes only
  `system` + `prompt` (engine.py:82-87); `request.context` never reaches the
  model. Casualty found: **`my-guide.wish()` passes the entire tool catalog in
  `context` and only the raw wish text as prompt** (guide.py:96-103) — against
  the real engine the model routes wishes without ever seeing the catalog,
  invisibly to my-guide's green CI. my-idea documents the workaround
  explicitly (explore.py:265-269: "grounding goes in the PROMPT"); most other
  tools use `context` only for cache-key/echo metadata, so the blast radius is
  my-guide plus any future tool that trusts the field's name. Wrinkle:
  `CachingEngine` *does* hash `context` (engine.py:116-127), so requests
  differing only in ignored context are cached as different entries.
- **Seam-level fix:** decide the contract and enforce it with a test that runs
  against every backend: either (a) `ClaudeCLIEngine` appends a serialized
  `context` block to the prompt, or (b) `context` is renamed/documented as
  cache-key-only metadata with a size-lint flagging any tool putting real
  grounding in it. (a) matches the field's name; (b) matches current usage.
  Either way, fix `my-guide.wish()` immediately.

**`_compat` honesty:** the good direction — claims satisfied by building the
capabilities, not by deleting the claims (MEASURED: 8 `core:` claims in
`tools_manifest.json`, all resolving; `python -m mythings._compat --check` →
"0 error(s), 0 pending claim(s)").

**Transferability:** the kernel — core's five contracts +
`_compat`/`_harness`/`_secrets`/`_devledger`, `my-template`, `my-guard`,
`my-orchestrator`, the two drivers — is cleanly separable from the
study/personal tools; nothing in core imports a tool (OBSERVED). Extracting
now is premature: the kernel's distinguishing claims (unattended safety, loop
economics) are exactly the unproven ones. Extract after a demonstrated
unattended week, not before.

**Verdict.** *Proven:* small deterministic tools + one seam + mechanical gates
can keep 41 repos simultaneously green with a repair burden one human can
absorb; resume-not-restart dispatch works; fail-closed policy plumbing works.
*Not yet disproven:* that the loop can run unattended safely and productively —
8 sessions over two days is anecdote, not evidence; and the engine seam has
now produced two silent-degradation bugs, so the paradigm needs a
**contract-test discipline on its one non-deterministic boundary** as much as
it needed gates on the deterministic side. *The single confidence-raising
experiment:* a supervised 72-hour `fleet_cycle.py --loop` on the Pi with
`--max-cycle-budget-usd 30`, App identity, ASK armed, and a written scorecard:
PRs opened/merged, needs_human count, repair ratio of the PRs it generates,
$ per merged PR.

### Q5 — LLM cost: measure, then cut

**Finding #1 is the meter, as predicted.** The split across (a) dispatched
workers / (b) per-tool Engine calls / (c) interactive dev sessions is
answerable only for (a): **MEASURED $9.50 all-time** (8 sessions: $6.62 on
07-07, $2.88 on 07-08), fully itemized in `.fleet-dispatch/ledger.jsonl`.
For (b): `ClaudeCLIEngine` receives `total_cost_usd` in the CLI's JSON reply
(it lands in `EngineResult.data`) **and no tool ledgers it** — a grep across
all `my-*/src` finds exactly one reader of `cost_usd` (my-reporter's digest,
which can only report what dispatch wrote). For (c): interactive sessions run
on subscriptions; `account_usage.py` probes the rolling 5-hour window but
nothing records history. Note also `fleet_usage.py` is a **library with no
CLI** despite the README/prompt framing — there is no runnable "where did the
money go" instrument. **Minimal fix:** a ~20-line ledger-writing Engine
wrapper (composed with `CachingEngine`) in each tool's `build_engine` factory:
`kind=engine_usage, tool, model, cost_usd, cache_hit`. One change makes (b)
visible and gives `--max-cycle-budget-usd` true coverage.

**Levers, audited for adoption (MEASURED by grep):**
- **Engine-result cache (core#97): built, adopted by zero tools.** No file
  outside core constructs `CachingEngine`. Hit rate: n/a. Wire it into the
  same factory as the meter.
- **Model tiering:** `--engine-model` plumbing exists in 20+ tools, but
  defaults are unset everywhere, so every real call uses the CLI default
  model. By judgment depth: *classification-shaped* (orchestrator tie-break,
  notes tag, archivist classify, changelogger fold, docs gloss, dashboard
  banner) — small model, near-zero risk, and the fence-stripping fix
  specifically de-risked small-model JSON; *synthesis* (researcher brief,
  data-analysist, director decompose, glossary) — mid; *code-writing workers
  + Guard's judge* — frontier only.
- **Pi + small model:** proven in practice by the my-idea batch (28 ideas
  triaged cheaply; ledger entries through 07-12). Every classification-shaped
  call above is eligible.
- **Dispatch efficiency (MEASURED from all 8 transcripts):** productive
  sessions run 56–103 turns with **3–4M cache-read input tokens each** —
  workers spend most of their input re-reading repo context turn after turn.
  Denial waste is a solved problem (~1% of output tokens; the allowlist
  auto-widen worked). The lever is turn count, not denials: injecting the
  repo's `CLAUDE.md` five-seam summary + `myreporter digest --handoff` into
  the dispatch prompt should shorten the look-around phase. (HYPOTHESIS —
  confirm by A/B over 5 dispatches comparing `num_turns`; the ledger's
  `rtk=true/false` field shows this measurement pattern already exists.)
- **Not making the call at all:** docs-page glosses, dashboard banner, and
  changelog folds are stable across cycles — `CachingEngine` memoization makes
  repeat cycles free; same wiring as the factory above.

**Rough cost model (current shape):** one full `--execute --dispatch-execute`
cycle ≈ 2 workers × ≤$3 + ~10–20 small Engine calls (≈$0.10–0.50 if metered)
≈ **≤$6.50/cycle worst case**; the $20/day dispatch cap bounds a week of
`--loop` at **≤$140/week dispatch** + unmetered Engine steps (estimated
single-digit $/week at current call counts — "estimated" being the problem the
meter fixes). **Top 3 cuts:** (1) meter + cache via the shared factory (makes
everything else measurable; repeat cycles become near-free on the stable
calls); (2) small-model defaults for the six classification-shaped calls
(~5–10× on that slice); (3) context injection into worker prompts (turn-count
cut on the dominant per-session cost; validate with the A/B above).
